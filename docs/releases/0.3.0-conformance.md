# 0.3.0 Conformance Contract

This tracked document defines candidate inputs; run-specific conclusions remain
operator-reviewed evidence for one immutable candidate SHA. CI may reproduce the
validation matrix, but it does not construct, attest, sign, upload, or publish a
release artifact.

Required gates are formatting, Clippy, stable/MSRV tests, warning-free rustdoc,
generation/provenance/coverage freshness, Rust scenarios, Miri, ASan/UBSan/TSan,
all fuzz targets, C++ pairings, CLAP/VST3/Audio Unit native jobs, dependency and
license audits, seven clean-room packages, and deterministic source-bundle
verification. Commands and runner ownership are normative in
`docs/conformance/ci-matrix.md`.

Before committing candidate bytes, run the following block on Linux or macOS.
`audit-api` intentionally rejects Windows because Windows libclang emits the
packed `ARAFactory` as opaque; Windows consumes the checked-in bindings and
proves them through its target-native Rust and C/C++ ABI jobs.

```text
cargo xtask release audit-api
cargo xtask release audit-unsafe
cargo xtask release audit-licenses
cargo xtask release verify-source-inputs --version 0.3.0
```

From the clean candidate commit, `source-bundle` creates the versioned archive and
`verify-source-bundle` regenerates its clean-room lockfile and builds all seven
members offline with a new empty Cargo home. The operator verifies the checksum,
reviews all 40 same-SHA validation fragments, runs package dry-runs in dependency
order, and alone decides whether to sign the tag and publish the crates.

The 40 fragments are a hard gate, not an informal review. With `COMMIT` set to the
candidate SHA, run `cargo xtask ci bundle-evidence --input
target/release-evidence/fragments --output
target/release-evidence/ara2-validation-$COMMIT.tar.zst --head-sha "$COMMIT"
--matrix docs/conformance/ci-matrix.md`; the command rejects missing, extra,
failed, or mixed-SHA fragments. Before tagging, run `cargo publish -p <crate>
--dry-run --locked` in this exact order: `ara2-bridge-sys`, `ara2-bridge-core`,
`ara2-bridge-plugin`, `ara2-bridge-host`, `ara2-bridge-companion`,
`ara2-bridge-testkit`, then `ara2-bridge`. The implementation plan contains the
complete copyable operator command block. Actual publication is a separate manual
decision and is never implied by passing these checks.

The bridge supports the redistributable ARA 2.3 public surface. The separately
licensed AAX API and Audio Unit v3 companion behavior are not claimed.
