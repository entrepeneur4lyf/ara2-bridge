# Phase 3 Handoff — Plug-in Runtime

Status: implementation gate complete  
Baseline: ARA API `releases/2.3.0`, normative commit `65ec5c43b943a48cb5446f448a0492db6af8534b`

## Implemented surface

`ara2-bridge-plugin` now provides immutable multi-factory registration, independent generation state, complete 54-slot document-controller dispatch, typed model registries, ARA1 graph normalization, all ARA2 model objects, scoped host audio/content/archive/update/playback clients, content snapshots for all six event kinds, analysis progress, complete and filtered persistence, algorithms, licensing, audio-file chunks, signal queries, realtime head/tail snapshots, reliable 2.3 dirty notifications, and all legacy/ARA2 extension roles.

Required authoring behavior is split across `DocumentLifecycle`, `MusicalContexts`, `RegionSequences`, `AudioSources`, `AudioModifications`, and `PlaybackRegions`. `PluginBuilder` composes optional providers. `FactoryBuilder::document_controller` creates one fresh model per document.

## Safety and lifecycle invariants

- Sized foreign records and nested arrays are copied before callback return.
- Model references use controller-owned stable tombstone cells; foreign, stale, and wrong-kind pointers are rejected without dereference.
- Mutations require editing, deactivation follows child-before-parent order, and destruction is leaf-first.
- Plug-in content readers exclude model mutations and are destroyed exactly once.
- Host content access is dispatcher-scoped. Owned host audio readers use a controller revocation registry and become inert after synchronous disable/destruction/teardown.
- Analysis is cancelled before source access revocation, deactivation, or destruction.
- Realtime head/tail dispatch reads immutable atomically selected storage without allocation or blocking locks.
- Factories, controller instances, content readers, and extension interfaces pass strict-provenance Miri ownership checks.

## Test fixture and generated artifacts

`ara2-bridge-testkit::build_test_factory` enables all six content kinds, analysis, partial persistence, two algorithms, licensing, chunk storage, signal preservation, head/tail, updates, and all extension roles. `plugin_contract` drives every generated document-controller callback through a real raw factory/controller, then drives every null-controller ABI fallback, and compares both 54-name sets with `PLUGIN_CONTRACT_TESTS`.

Mechanical callback code is generated by `cargo xtask ara plugin-dispatch --write` and checked with `--check`. Do not edit `ffi/generated_callbacks.rs` directly.

## Revisions discovered during implementation

- Controller hooks now receive explicit host scopes; previously implemented host wrappers were unreachable to application code.
- Host audio readers changed from self-borrowing wrappers to owned, synchronously revocable handles.
- The raw factory allocation uses pointer ownership that survives Rust moves under strict provenance.
- The workspace graph records the plug-in crate's necessary direct downward dependency on `ara2-bridge-sys`.
- A handwritten capability test used an ABI-incompatible licensing callback cast (`i32` instead of `ARASize`); strict-provenance Miri found it and the test now uses the exact generated ABI aliases.
